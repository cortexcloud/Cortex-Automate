# ทดสอบการ์ดตาม TC ใน Sub-Issue แล้วแนบผลลง Linear

สกิลนี้เก็บ**ลำดับงาน**ที่ผู้ใช้สั่งเมื่อ 6 ต.ค. 2026 (การ์ด SBH-2394):
"ช่วยทดสอบการ์ด … เล่นตาม Test Case ที่มีอยู่ใน Sub Issue แล้ว … แนบผลการทดสอบ โดยเป็นรูปและคลิป … ถ้าสงสัย … ถามได้เลย และเก็บเป็น Skill ไว้ด้วย"

กฎของโปรเจกต์ · โครงสร้าง · คำสั่งอยู่ในสกิล `cortex-automate` — **โหลด SKILL.md ของมันก่อนเริ่ม** (ไฟล์เล็ก = กฎ + ดัชนี) แล้วทำตามนั้นเมื่อขัดกับไฟล์นี้ ·
จากนั้น **อ่านเพิ่มเฉพาะที่การ์ดนี้ใช้**: Grep เลขการ์ดใน `cortex-automate/references/decisions.md` (คำตอบเดิมของผู้ใช้) และใน `references/changelog.md` ของสกิลนี้ (เคยทดสอบไหม) ·
เปิด `cortex-automate/references/screens/<โมดูลของการ์ด>.md` (er / opd / pharmacy-refill / refer / sbh-prod …) — Grep ชื่อหน้าจอก่อน Read · ไม่โหลด screens ของโมดูลอื่น
**ทุกขั้นในลำดับงานด้านล่าง แจ้งสถานะผู้ใช้เป็นระยะ (R44)**: ก่อนเริ่มขั้น · ทันทีที่ติดปัญหา (ติดอะไร กำลังแก้อย่างไร) · เมื่อจบขั้น — ไม่ทำเงียบยาวแล้วสรุปตอนจบ
งานจบแล้วมีอะไรเปลี่ยน (ขั้นตอน / กับดัก / คำตอบของผู้ใช้) → แก้ไฟล์นี้ และเพิ่ม 1 บรรทัดใน `references/changelog.md` ของสกิลนี้

## ลำดับงาน

### 1) อ่านการ์ดและ Sub-Issue ให้ครบก่อน

- `get_issue` การ์ด (+ `includeRelations`) · `list_comments` · รูปในการ์ดเปิดด้วย `extract_images` (การ์ดบางใบมีแค่รูป)
- ไล่ Sub-Issue ด้วย `list_issues parentId=…` ทีละชั้น: การ์ด → `EXE - CT - …` → `SC-00x` → `TC-00x` แล้ว `get_issue` ทุก TC (รายการแบบ list ตัดคำอธิบาย)
- ใต้การ์ดอาจมีสเปกของ dev (เช่น "Spec: …") — อ่านด้วย บอกพฤติกรรมจริง / ชื่อ component / สิทธิ์ / สิ่งที่อยู่นอก scope
- คำอธิบายของ EXE สำคัญที่สุด: **Pre-condition** · **Scope ของชุด** · **ข้อควรรู้ก่อนรัน** · **ยังไม่ทำในชุดนี้** · ระบบที่รันได้ (Dev-X / SBH Prod)
- TC ของชุดอื่นที่ EXE อ้างถึง เปิดดูผลเทสมือ (มีคลิปเดิมของผู้ใช้) ไว้ดูว่าผู้ใช้ลงผลหน้าตาแบบไหน

### 2) ตรวจว่า TC ครอบคลุมไหม (R16)

- จับคู่บรรทัดในการ์ดกับ TC · เคสที่ EXE จดไว้ว่า "ตกลงยังไม่ทำ" **ไม่ต้องเสนอซ้ำ** แค่บอกว่ารู้
- มีช่องว่างจริงค่อยเสนอ TC ในแชท (ผู้ใช้ตัดสินว่าจะเพิ่มลง Linear ไหม)

### 3) ตรวจว่ารันที่ระบบไหนได้ — เริ่มที่ dev-x แบบอ่านอย่างเดียว

ทำได้เลยไม่ต้องถาม (dev-x เป็นระบบตั้งต้น):
- ฟีเจอร์ขึ้นระบบหรือยัง: โหลด `/cortex/` หาชื่อ `assets/index-<hash>.js` แล้ว grep ชื่อ component / สิทธิ์จากสเปก (ข้อความไทย grep ไม่เจอ · เลข `APP_VERSION` เชื่อไม่ได้)
- มีข้อมูลตาม Pre-condition ไหม: สคริปต์ node ใน scratchpad ขอ token ด้วย password grant (`cortex-ui`) แล้ว `GET` API ที่เกี่ยวข้อง — อ่านอย่างเดียว ไม่พิมพ์รหัสผ่าน / token
- dev-x รันไม่ได้ → เก็บเหตุผลเป็นตัวเลข (API ตอบอะไร · ตรวจกี่รายการ) ไว้ลงช่อง Test Result ของ Dev-X

**SBH Prod ยังห้ามแตะจนกว่าผู้ใช้อนุญาตสำหรับการ์ดนั้น** (R40 — การอนุญาตของการ์ดก่อนใช้กับการ์ดใหม่ไม่ได้)

### 4) ส่งสรุป + แผน แล้วถามครั้งเดียว
