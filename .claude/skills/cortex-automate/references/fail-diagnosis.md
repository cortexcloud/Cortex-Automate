# วินิจฉัยเทสที่ fail

ปรับจากสกิล Flaky Test Doctor (qaskills.sh, MIT) ให้เข้ากับโปรเจกต์นี้ (R52)

**หลัก:** วินิจฉัยแล้วเสนอวิธีแก้เท่านั้น — ห้ามแก้ spec / helper หรือ skip เทสเองจนกว่าผู้ใช้อนุมัติ diff นั้น

## 1) เก็บหลักฐานก่อนสรุป

| หลักฐาน | อยู่ที่ไหน | ใช้พิสูจน์อะไร |
|---|---|---|
| trace | `test-results/<เทส>/trace.zip` (config เก็บไว้ตอน fail อยู่แล้ว) | ลำดับ action · DOM · network · console |
| ภาพ checkStep / ภาพตอน fail · วิดีโอ | report + `test-results/` | หน้าจอจริงตอนพัง ต่างจากที่คาดยังไง |
| error + บรรทัด + ขั้นที่พัง | report | พังที่จุดเดิมหรือคนละจุด |
| network ของ Cortex API | trace | มี 4xx / 5xx หรือช้าผิดปกติตอนพังไหม |
| ผลรันก่อนหน้า | report / `.cache/` / ผลที่แนบใน Linear | เคยผ่านด้วยโค้ดเดิมไหม |

ห้ามสรุปจาก error message อย่างเดียว — "หา element ไม่เจอ" หลายครั้งเป็นเพราะ backend ช้า ไม่ใช่ locator ผิด

## 2) แยกประเภท

ต้องมีหลักฐานอย่างน้อย 2 อย่าง ไม่ถึงให้ตอบ "ยังไม่รู้" พร้อมวิธีพิสูจน์

| ประเภท | สัญญาณ | ใครแก้ |
|---|---|---|
| **ระบบพังจริง** | 5xx / JS error ตอนพัง · คนกดเองก็เป็น · บันทึกซ้ำได้ 2 รายการ · ข้อมูลไม่อัปเดตหลังบันทึก | dev → เปิดการ์ดบั๊กตาม R48 |
| **เทสเขียนผิด** | `waitForTimeout` แทนการรอเงื่อนไข · assert ตามลำดับรายการ · locator เจอหลายตัว / 0 ตัวเป็นบางครั้ง · ลืม `await` | เรา |
| **สภาพแวดล้อม** | dev-x ช้า / ล่มช่วงเวลาหนึ่ง · session หมดอายุ · Keycloak | แจ้งผู้ใช้ / รันใหม่ภายหลัง |
| **ข้อมูล** | ผู้ป่วย AUTO / Visit ค้าง (R11) · HN หรือเลขชุดชน · ข้ามเที่ยงคืนแล้วนับเป็นวันใหม่ | เรา (ข้อมูล / ขั้นเตรียม) |
| **ยังไม่รู้** | หลักฐานไม่พอ | เสนอวิธีพิสูจน์ที่ชี้ขาดได้ |

⚠️ **ความผิดพลาดที่อันตรายที่สุด** คือระบบมีบั๊กจริง แต่ไปเหมาว่าเทสไม่เสถียร — ถ้าแพทย์ / พยาบาลกดแบบใน trace
แล้วเกิดผลเดียวกันได้ ให้ถือเป็น "ระบบพังจริง" ไว้ก่อน จนกว่าจะพิสูจน์ได้ว่าไม่ใช่

## 3) พิสูจน์ด้วยการรันซ้ำ

- **dev-x:** `npx playwright test <ไฟล์> --grep @SBH-xxxx --repeat-each=5 --retries=0 --workers=1`
  ใช้ได้เฉพาะเทสอ่านอย่างเดียว หรือเทสที่สร้างข้อมูลแล้วปิด Visit เอง · บอกผู้ใช้ก่อนว่าจะสร้างผู้ป่วย AUTO กี่ราย
- **SBH Prod: ห้าม `--repeat-each`** — สร้างคนไข้จริงเพิ่ม และขัดกฎรันแบบเปิดจอทีละราย · บน Prod ให้วินิจฉัยจาก
  หลักฐานรอบเดิม ถ้าจำเป็นต้องรันใหม่ ถามผู้ใช้ก่อนทุกครั้ง
- คง `retries: 0` ใน config — retry ช่วยซ่อนบั๊ก ใช้เพิ่มได้เฉพาะชั่วคราวพร้อมงานที่ต้องแก้ตามมา และต้องให้ผู้ใช้อนุมัติ

## 4) รายงานผล (ต่อเทส)

```
### วินิจฉัย: <ชื่อเทส / TC>
- ประเภท: เทสเขียนผิด (ความมั่นใจ: สูง / กลาง / ต่ำ)
- ผลรันซ้ำ: fail 2/5 รอบบน dev-x · พังที่ขั้นเดิมทุกครั้ง
- หลักฐาน: 1) trace … (action ที่ … ) 2) …
- เสนอแก้ (ยังไม่แก้): <ไฟล์:บรรทัด> + diff
- ผู้แก้: เรา / dev (เปิดการ์ดบั๊ก)
```

- ทุกหลักฐานต้องอ้างที่มาจริง (ไฟล์ · บรรทัด · action ใน trace)
- ถ้าเป็น "ระบบพังจริง" ต้องบอกผลกระทบที่แพทย์ / พยาบาลจะเจอ

## 5) วิธีแก้ (ทำหลังผู้ใช้อนุมัติ)

| สาเหตุ | แก้แบบนี้ | ห้ามทำ |
|---|---|---|
| `waitForTimeout` | รอเงื่อนไข: `expect(locator).toBeVisible()` / `toHaveText()` / `waitForResponse` | เพิ่มเวลารอ |
| assert ตามลำดับ | เรียงก่อนเทียบ หรือเช็กว่ามีอยู่ในรายการ | assert ตาม index |
| ข้อมูลชน / ค้าง | ข้อมูลใหม่ทุกรอบ (R10) · ปิด Visit ในขั้นเก็บกวาด | ลบข้อมูลคนอื่นกลางเทส |
| ระบบพังจริง | เปิดการ์ดบั๊กพร้อม trace · ปล่อยให้เทส fail | skip เทสให้ผลเขียว |
