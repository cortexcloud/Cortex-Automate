### Mock Data UAT ER — ความรู้หน้าจอ (สำรวจบน dev-x 3 ต.ค. 2026)
- **ER Physician Note บังคับ Vital Signs แล้ว** (ไม่กรอก → "กรุณากรอกข้อมูล" ใต้ช่อง Temperature) · มีช่อง `Order to Nurse` / `Note to Nurse` เพิ่ม ·
  **ผู้ป่วยที่คัดกรองโดยไม่กรอกสัญญาณชีพ → บันทึก Note ได้ 500** `{"message":"Internal server error"}` หน้าจอเงียบ (dev-x) · คัดกรองพร้อมสัญญาณชีพแล้วบันทึก Note ได้ 201 (ฟอร์มดึงสัญญาณชีพจากคัดกรองมาให้) + `PATCH …/encounters/<EN>/treatment-complete` ·
  กดบันทึกเร็วไปหลังเลือก Dx ฟอร์มไม่ส่งอะไรเลย และ `PUT /cortex-api/drafts` ไม่ได้ยิงทุกครั้ง (รอ draft ไม่ได้) → `savePhysicianNote()` กดซ้ำจนเห็น contribution ที่ body มี `sbh_er_physician_note`
- **One Day Order**: ค้นด้วยรหัส → ตัวเลือกไม่มี `title` จับด้วยข้อความ `[<รหัส>]` → `plus เพิ่มลงตะกร้า` (graphql `UpsertOpdOrder` · ฟอร์ม Lab / รังสี / หัตถการ กดเพิ่มได้เลยด้วยค่าตั้งต้น) → แถวในตะกร้าชื่อ `ยังไม่ส่ง [รหัส] …` →
  `save ส่งคำสั่ง` (graphql `SignOPDOrders` → `{accepted:true}` · HTTP 200 แม้พัง ต้องดู `errors`) → แถวเป็น `ส่งแล้ว [รหัส] …` · ยกเลิกรายการ = ปุ่ม `ยกเลิก` ในแถว → popconfirm `ยืนยัน`
  - รายการรังสีที่ผูกแบบฟอร์ม: กดส่งครั้งแรกเด้ง dialog `แบบฟอร์ม Imaging - X-Ray` (ไม่บังคับช่องใด) → `save บันทึก` (`PUT /cortex-api/imaging-order-form-compositions` + toast "บันทึกแบบฟอร์ม Imaging สำเร็จ") → **ต้องกดส่งคำสั่งอีกครั้ง**
  - หัตถการ `SBHACT62` บน dev-x: ส่งคำสั่งแล้ว toast "เกิดข้อผิดพลาดในระบบ" — `failed to create activity tasks … activity category 11 is inactive or not found` และทำให้รายการอื่นในตะกร้าไม่ถูกส่งด้วย (category ที่ใช้ได้ดู `GET /generated-emr-api/activity-categories`)
  - รหัสบน dev-x: Lab `SBHLAB399` (CBC) · รังสี `SBHIMG1` (CHEST) · รหัสในชีต Mock-Data ER (`LAB0000001`, `IMG0000194`, `ACT…`) เป็นของ Prod ค้นบน dev-x ไม่เจอ
- **งานพยาบาลเกิดเองจาก Order Lab / รังสีที่ส่งแล้ว** รายการละ 1 งาน สถานะ `PENDING` (= รอรับงาน): `GET /cortex-api/er/nurse-tasks?en=<EN>` (หรือ `?date=`) · สรุป `GET …/nurse-tasks/summary?date=` → `{active,pending,running,overdue}` ·
  หน้า `/cortex/er/nurse-task-list?nurseTaskDate=` (เมนู ER "รายการงานพยาบาล") **บน dev-x เปิดไม่ได้** — `GET …/nurse-tasks/encounters` → 500 → ยังไม่รู้ปุ่มรับงาน (ทำให้เป็น "กำลังทำ")
- **ฟอร์มคัดกรอง ER ส่วนเพิ่ม (ตรวจ 14 ต.ค. 2026 · SBH-1057):** Vital Signs หลายชุด = ปุ่ม `+ เพิ่มรายการ` ตัวแรกในฟอร์ม → `heading "วัดครั้งที่ 2"` (spinbutton ซ้ำชื่อ → ใช้ `.nth(i)` · `expectTriageFormOpen()` พังด้วย strict mode เมื่อมีหลายชุด) · Temp > 37.5 ขึ้นแดง "ต้องไม่มากกว่า 37.5" แต่ยังบันทึกได้ ·
  Body metric: spinbutton `Weight` / `Height` → textbox `BMI` / `BSA` (disabled · BSA สูตร Mosteller) · CC: กดชิปแล้วคำลง `textarea[placeholder="สรุปอาการและอื่น ๆ"]` ให้ · **ประวัติแพ้ในฟอร์ม** = ปุ่ม `+ เพิ่มรายการ` ตัวสุดท้าย → แถว (select แพ้ยา/แพ้อาหาร/แพ้อื่นๆ · textbox `ระบุชื่อยา/สิ่งที่แพ้` · `ระบุอาการแพ้/สรุปอาการแพ้` · ผลการประเมิน `Unverified` · ปุ่ม `ลบ` ไม่มีกล่องยืนยัน) —
  **ไม่ดึงจากประวัติแพ้ยาของผู้ป่วย และไม่เข้าประวัติแพ้ยา** (ผู้ใช้อธิบาย: เป็นการสำรวจเบื้องต้น แพทย์บันทึกแยกทางขวา) หลังบันทึก Triage แสดงที่หน้า Overview · ทุกช่อง (รวม Vital Signs หลายชุด / Allergy) เก็บเป็น draft `PUT /cortex-api/drafts` 204 → โหลดหน้าใหม่ค่ายังอยู่ · ไอคอนวงกลมหน้า "คัดกรอง ER" ว่าง = ยังไม่บันทึก · ถูกสีเขียว = บันทึกแล้ว (ไม่มีข้อความ กำลังบันทึก) ·
  ปุ่ม `ใช้ข้อมูลล่าสุด (ภายใน 24 ชั่วโมง)` ดึงค่าวัดล่าสุดของผู้ป่วยพร้อมเวลาวัดเดิม (ไม่ดึง Pain score · ไม่มีข้อมูล = ไม่เกิดอะไร) · ค้น HN ที่หน้าคัดกรอง: ค้นชื่อก่อน (ขึ้น "ไม่พบผู้ป่วย" ชั่วครู่) แล้วค่อยค้น HN — เลือกเร็วไปจะพัง
- **บันทึกแพ้ยาไม่ต้องมี Visit**: หน้าผู้ป่วย `/cortex/next/patients/<HN>` → เมนูขวา `บันทึกการแพ้` → แท็บ `แพ้ยา`: combobox `* ชื่อยา` (พิมพ์ค้น · ตัวเลือกยาผสมจะบันทึกแพ้ทุกตัวยา) · `* ประเภทของการแพ้ยา` · textbox `* สรุปอาการแพ้` · ผลการประเมิน (select ไม่มีชื่อ placeholder "เลือกผลการประเมิน": Unconfirmed / Confirmed / Refuted) · `* Severity` (Mild / Moderate / Severe) · `* การแจ้งข้อมูลการแพ้ยาคนไข้` → `save บันทึก` (graphql `CreateMedicationAllergy`) → แถบหัวขึ้น `แพ้: <ยา> (SUBS)` · ดูย้อนหลังที่เมนูซ้าย `ประวัติการแพ้`
- **เปิด Visit OPD**: หน้าผู้ป่วยที่ยังไม่มี Visit → เมนูขวา `จัดการ Visit` → select "คลินิก" (พิมพ์ "อายุรกรรม" → `MED - ห้องตรวจโรคอายุรกรรมทั่วไป` clinicId 11) · ตารางสิทธิใส่ `H01 - เงินสด` มาให้ → ปุ่ม `สร้าง` (graphql `CreateVisit` → vn + en สถานะ `pending-check-in`) → URL `?actions=editVisit&editVN=<VN>` · ไม่มี toast
  - **แพทย์ของ Visit**: แถว Walk-in มี select แพทย์ (ค่าตั้งต้น = แพทย์คนแรกที่มีตารางออกตรวจของคลินิกนั้น · ตัวเลือกมีเฉพาะแพทย์ของคลินิกนั้น) — คลิก `.ant-select` ในแถว (คลิก input ตรงๆ โดนชื่อบัง) → พิมพ์ค้น → เลือก · `openOpdVisit()` ไม่เจอชื่อที่ตั้งไว้จะพังพร้อมรายชื่อที่มี
  - **เช็คอิน Visit OPD**: หน้า editVisit ไม่มีช่องสถานะ → เปิด `/cortex/next/patients/<HN>?en=<EN>&vn=<VN>` → ช่อง `สถานะ` บนแถบหัว (`.ant-select[class*="status-select"]` มีตัวซ่อนอีกตัว ใช้ตัวที่ visible) ตัวเลือก `รอเช็คอิน / เช็คอิน / ยกเลิก` → `เช็คอิน` (graphql `CheckInEncounterStatus` → `accepted:true` + คิวตรวจ เช่น `B101`) → ระบบยิง `POST /cortex-api/queues/print-slips` เอง · ผู้ป่วยย้ายไปแท็บ "เช็คอิน" ของรายการผู้ป่วยนอก → `checkInOpdVisit()` · เคยเห็น toast "เกิดข้อผิดพลาดในระบบ" 1 ครั้งทั้งที่สถานะเปลี่ยนแล้ว (ไม่ได้เก็บ API ไว้)
- กับดักจังหวะของ One Day Order: กด `เพิ่มลงตะกร้า` ทันทีหลังเลือกรายการ = เงียบ ไม่ยิง `UpsertOpdOrder` (ฟอร์มยังเติมค่าตั้งต้นไม่เสร็จ) · กด `ส่งคำสั่ง` ทันทีหลังเพิ่มรายการ = ค้างที่ toast "กำลังตรวจสอบแบบฟอร์ม Imaging" ไม่เด้งฟอร์ม → `submitOrders()` กดซ้ำด้วย `expect(...).toPass()`
- แถบเมนูขวากางค้างบังปุ่ม `ส่งคำสั่ง` — คลิกหัวข้อเนื้อหา (เช่น heading "Order") + ย้ายเมาส์ (`openCareMenu()` ใน `mock-data/uat-er.ts`)
- เมนู ER บน dev-x: แดชบอร์ด / คิว · รายการงานพยาบาล · รายงานทางสถิติ · ตั้งค่า — **ไม่มี "รับ Refer เข้า"**

### เล่น Scenario UAT ER — ความรู้หน้าจอ (dev-x v2.2.4 · 3 ต.ค. 2026 · ผลเต็มใน §10)
- **หน้าผู้ป่วยที่เพิ่งโหลดเปิดแผงตั้งต้น (ER Physician Note) ตามหลัง** แล้วทับแผงที่เพิ่งกดจากเมนูขวา → `careMenu()` กดซ้ำจนแผงขึ้น · ชื่อ menuitem มีชื่อไอคอนนำหน้า (ใช้ regex ลงท้าย ไม่ใช้ exact) · เมนูขวา: Consult · CPR Progression · ER Physician Note · Disposition · สร้าง Admit Order · จัดการ Admission · สร้างฟอร์ม · ใบรับรองแพทย์ · One Day Order · Order Summary
- **dropdown ที่อยู่ชิดขอบล่างของจอ ตัวเลือกไม่นิ่งให้กด** (actionability ค้าง "stable") → `pick()` กดปกติ 4 วินาทีแล้ว fallback `click({ force: true })` · แถบเมนูขวากางทับปุ่มมุมขวาบน (ลงนาม) ตอนเมาส์อยู่ฝั่งขวา → คลิกเนื้อหา + ย้ายเมาส์ก่อน
- ฟอร์มใน `cortex-form` (คัดกรอง / Physician Note / Progress Note / CPR) อยู่ใน shadow DOM — **XPath ไม่ทะลุ** · `POST /ehrbase/plugin/transform-composition/flat-to-json` เป็นแค่การแปลงฟอร์ม ไม่ใช่การบันทึก (ตัวบันทึก = `…/contribution`) → อย่าใช้ pattern กว้างๆ จับ "บันทึกสำเร็จ"
- ยกเลิก Encounter จากช่องสถานะ: ตัวเลือก `ยกเลิก` → dialog ชื่อ `ต้องการยกเลิก 'EN …' ใช่หรือไม่?` · textbox `ระบุเหตุผลการยกเลิก` (≤ 80) · ปุ่ม `ย้อนกลับ` / `ยืนยัน` → **ใช้ได้แล้ว** (29 ก.ย. เคย 500) · มุมมองรายการ: `searchbox "ค้นหา HN"` + แท็บมีตัวนับ (`ยกเลิก 1`)
- ผู้ป่วยที่ยกเลิก Visit ER แล้ว เปิด Visit ER ใหม่วันเดียวกันได้ (ราย C: ยกเลิกใน UAT-ER-10 → ใช้ต่อใน UAT-ER-01)
- **Consult** (เมนูขวา): combobox `ขอปรึกษาไปยังคลินิก` / `แพทย์ขอปรึกษา` (ต้องมีอย่างน้อย 1 อย่าง · เลือกคลินิกแล้วรายชื่อแพทย์ถูกจำกัดตามคลินิก — อายุรกรรมไม่มี "ทดสอบ มานะ" · ไม่เลือกคลินิกค้นแพทย์ได้ทั้งระบบ ค้นด้วยนามสกุล "มานะ" เพราะค้น "ทดสอบ" ได้ชื่อคล้ายกันเกินหน้าแรก) · ช่อง Consult Problem เป็น contenteditable · `save บันทึก` → graphql `CreateConsultRequest` (`sourceType: er`)
  - **ตอบได้เฉพาะแพทย์ที่ถูกขอปรึกษา** (R33): ประวัติ Consult (เมนูซ้าย) → แถวสถานะ `รอตอบกลับ` ปุ่ม `ตอบกลับ consult` → dialog `Consult`: radio `ตอบ Consult` / `ปฏิเสธ Consult` · editor ตัวแรก = `คำตอบ *` ตัวที่ 2 = ข้อแนะนำ/แผนการรักษา · checkbox `Print ใบนัดอัตโนมัติ` · `บันทึก` → dialog `ยืนยันการบันทึกข้อมูลหรือไม่? หากบันทึกแล้วจะไม่สามารถกลับมาแก้…` → `ยืนยัน` → แถวเป็น `ตอบแล้ว` · ผู้ขอเปิดแถวเดิมเห็นคำตอบ
  - ผู้ขอเปิดคำขอของตัวเอง / แพทย์คนอื่นเปิดคำขอที่ส่งถึงคลินิกอย่างเดียว: dialog มีแค่ "คำตอบ: ยังไม่มีการตอบกลับ" + `ปิด` (ไม่มีช่องกรอก) · role Doctor บน dev-x = "ดร. วิชัย รัตน์ เอื้อเฟื้อ" · คำสั่งบันทึกคำตอบไม่ผ่าน API ชุดที่ `watchMutations` ดู → ยืนยันผลจากสถานะแถว
- **ใบรับรองแพทย์** (เมนูขวา): select `ค้นหาเอกสารที่ต้องการสร้าง` (เปิดเร็วไปว่าง — ปิดแล้วเปิดใหม่) → ฟอร์ม เช่น "ใบรับรองแพทย์ 5 โรค (ภาษาไทย)" ช่องบังคับ `สรุปความเห็นของแพทย์` (ข้อความ error เป็น key ดิบ `opdMedicationDocumentRequiredError`) → `save บันทึก` → ขึ้น "สร้างโดย: … เวลา" (ตัวนับ "เอกสารที่สร้างแล้ว" ยังเป็น 0)
- **สั่งยา**: ต้องระบุ ขนาดยา + **Route** + ความถี่ จึงได้ `* วิธีใช้` · ไม่ระบุ Route แล้วกด `เพิ่มลงตะกร้า` = เงียบ · สคริปต์ยังเลือก Route ไม่ได้ (select ตัวที่ 2 ถัดจากช่องขนาดยา กดไม่ติด) — เล่นมือได้ (29 ก.ย.)
