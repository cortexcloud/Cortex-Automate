# ER flow: ผู้ป่วยใหม่ → เปิด Visit → Triage → Dashboard

ทำครบ flow ผ่าน Playwright MCP เมื่อ 26 ก.ย. 2026 (Super_User `user1`) · locator ในนี้คือตัวที่ MCP สร้างให้แล้ว**กดได้จริง**
ใช้เป็นจุดเริ่มเขียน spec ได้เลย (ถ้าหน้าจอเปลี่ยน ให้เชื่อหน้าจอจริง แล้วแก้ไฟล์นี้)

## 1) ลงทะเบียนผู้ป่วยใหม่ — `/cortex/er/triage`

- เลือก radio: `page.locator('label').filter({ hasText: 'ผู้ป่วยใหม่' }).click()`
- ช่องบังคับ 5 ช่อง (มี `*` ในชื่อ):
  | ช่อง | locator | หมายเหตุ |
  |------|---------|----------|
  | เลขบัตรประชาชน | `getByRole('textbox', { name: '* เลขบัตรประชาชน' })` | 13 หลัก — สุ่มแบบ checksum ถูกต้อง (R8, ดูด้านล่าง) |
  | ชื่อ | `getByRole('textbox', { name: '* ชื่อ' })` (id `firstName`) | |
  | นามสกุล | `getByRole('textbox', { name: '* นามสกุล' })` (id `familyName`) | |
  | เพศ | `getByRole('combobox', { name: '* เพศ' })` แล้ว `.ant-select-item-option[title="ชาย"]` | option ค่า `male` / `female` |
  | วัน/เดือน/ปีเกิด | `getByRole('textbox', { name: '* วัน/เดือน/ปีเกิด' })` (id `birthDate`) | **พิมพ์ `DD/MM/YYYY` เป็น ค.ศ. ได้เลย** (`15/01/1990` → ระบบแสดงวันเกิด 15 ม.ค. 2533) ไม่ต้องเปิดปฏิทิน · **ออกจากช่องด้วย Tab** — ถ้าช่องบังคับครบแล้วกด Enter ระบบส่งฟอร์มลงทะเบียนทันที (เจอ 26 ก.ย. 2026) |
- ไม่บังคับ: เบอร์มือถือ (+66) · รูปโปรไฟล์ · **ที่อยู่ตามทะเบียนบ้าน** / **ที่อยู่ปัจจุบัน** (เพิ่มเข้ามาหลัง 16 ก.ย. — เรื่อง `SBH-2140`)
  - `#officialAddress_houseNo` · ตำบล: `#officialAddress_locationLabel` พิมพ์ทีละตัว (`pressSequentially`) แล้วคลิก option ตาม title
    เช่น `ปากเพรียว` → `ปากเพรียว เมืองสระบุรี สระบุรี 18000` (ระบบเติมรหัสจังหวัด/อำเภอ/ตำบล/ไปรษณีย์ให้เอง)
  - ปุ่ม `ที่อยู่เดียวกัน` คัดลอกไปที่อยู่ปัจจุบัน (ช่อง `#currentAddress_*`)
  - **ไม่กรอกที่อยู่เลยก็ลงทะเบียนผ่าน** (ตรวจ 26 ก.ย. 2026 — spec SBH-1013 กรอกแค่ 5 ช่องบังคับ · 16 ก.ย. เคย 400 `address.officialAddressLine`)
- ปุ่ม `ลงทะเบียนผู้ป่วย` (คีย์ลัด Ctrl + Enter) → `POST /cortex-api/patients/er-registration` 200 → เปิด modal **เปิด Visit ER** ให้เองพร้อม HN
  - HN อยู่ที่ `patient.data.hn` ใน response (ในนั้นมี `patientId`, `namePrefix`, ชื่อ, `ehrId` ฯลฯ ด้วย)

**สุ่มเลขบัตรประชาชน** (checksum หลักที่ 13 = `(11 - Σ dᵢ·(14-i) mod 11) mod 10`, i = 1..12):
```ts
function randomThaiId(): string {
  const d = [1 + Math.floor(Math.random() * 8)];
  for (let i = 1; i < 12; i++) d.push(Math.floor(Math.random() * 10));
  const sum = d.reduce((s, v, i) => s + v * (13 - i), 0);
  return [...d, (11 - (sum % 11)) % 10].join('');
}
```

## 2) เปิด Visit ER (modal)

- `getByRole('dialog', { name: 'เปิด Visit ER' })` · หัว modal แสดง `HN <เลข>` + ชื่อ · ปุ่มล่าง `ยกเลิก` / `ยืนยันเปิด visit` · ปุ่ม `Close` (X) มุมบน
- ค่าที่ตั้งมาให้: Walk-in · ห้องตรวจแผนกฉุกเฉิน · แพทย์ `- ไม่ระบุแพทย์ ไม่ระบุแพทย์` · เวลานัด = ชั่วโมงปัจจุบัน · ตารางสิทธิว่าง
- **ต้องเลือกสิทธิ** (ไม่งั้น 422 `CoverageInput`): combobox สิทธิ**ไม่มีชื่อ** (มีแค่ข้อความ placeholder "สิทธิการรักษา") →
  `dialog.locator('.ant-select').filter({ hasText: 'สิทธิการรักษา' }).getByRole('combobox').fill('H01')` → `.ant-select-item-option[title="H01 - เงินสด"]`
  → ตารางสิทธิมี cell `H01 - เงินสด` · dropdown ยังค้าง ให้คลิกหัว modal (`dialog.getByText('เปิด Visit ER', { exact: true })`) เพื่อปิด (อย่ากด Esc)
- ยืนยัน: **`getByTestId('create-visit-submit')`** (ปุ่ม "ยืนยันเปิด visit" — มี test id)
- ผล: `POST /cortex-api/er/visits` 200 → toast `สร้าง Visit สำเร็จ` · response **ไม่มีตัวห่อ `data`**:
  `registration.{hn, vn, en}` · `registration.queueBinding.qDisplay` · `registration.isUnidentified` · `visit.encounters[0].clinicId` (6 = ห้องตรวจนอกเวลาราชการ)
  → ไปหน้า `/cortex/next/patients/<HN>?en=<EN>&vn=<VN>&fromApp=er` (ขั้น `1 Triage`)
- กด `ยกเลิก` → modal ปิด ผู้ป่วยได้ HN แล้วแต่**ไม่เกิด Visit** (ตรวจแล้วว่าไม่มี `POST /er/visits`) — spec เคยใช้วิธีนี้เตรียมผู้ป่วยมี HN ก่อนเปลี่ยนเป็น R15
- ผู้ป่วยที่ **Admit อยู่** (Admission `in-progress`): modal เปิดได้ปกติ แต่กดยืนยันแล้ว `POST /er/visits` → **400** `ErrVisitBlockedByActiveAdmission` ("visit creation is blocked by an active admission")
  — แอปไม่เช็คให้ก่อน (ตอนเลือกผู้ป่วยไม่มี API เรื่อง Admission) เจอกับ `6931253 คนไข้ Y4 ER Y4` 26 ก.ย. 2026
  — หน้าจอขึ้น toast "การรับผู้ป่วยในถูกล็อกและไม่สามารถแก้ไขได้" (ไม่บอกตรงๆ ว่าผู้ป่วย Admit อยู่) · modal ยังเปิดค้าง
- **ไม่เลือกสิทธิแล้วกดยืนยัน**: `POST /er/visits` → 422 `UnprocessableEntity` (`CoverageInput` failed on 'min') · หน้าจอขึ้นแค่ toast กลางๆ "ไม่สามารถประมวลผลคำขอได้"
  ไม่บอกว่าต้องเลือกสิทธิ · modal ยังเปิด · ไม่เกิด Visit (ตรวจ 26 ก.ย. 2026)

## 2.1) ผู้ป่วยมี HN → ค้นหาแล้วเปิด Visit (ตรวจกับ spec SBH-1013 26 ก.ย. 2026)

- radio: `page.locator('label').filter({ hasText: 'ผู้ป่วยมี HN' }).click()` (เป็นค่าเริ่มต้นอยู่แล้ว)
- ค้นหา: `getByRole('combobox', { name: 'ค้นหาผู้ป่วยด้วย HN หรือชื่อ' }).fill('<HN>')` → ผลค้นหา `.ant-select-item-option[title^="<HN> - "]`
  (title เต็ม = `<HN> - <คำนำหน้า ชื่อ นามสกุล>` เช่น `6931485 - น.ส. Claude ERGreen`) → คลิก → modal **เปิด Visit ER** แล้วทำต่อตามข้อ 2
- API ค้นหา: `GET /new-demographic-api/patients/<ข้อความ>` (404 `PatientNotFoundError` ถ้าไม่ใช่ HN เต็ม) + `GET /new-demographic-api/patients?page=1&perPage=10&filter[name][startsWith]=<ข้อความ>`
  → `{ data: [{ hn, firstName, familyName, namePrefix, gender, birthDate, deceased (boolean), identityVerificationMode, ... }], _metadata: { page, perPage, totalCount, totalPage } }`
  - `filter[name][startsWith]` จับทั้ง**ชื่อหรือนามสกุล**ที่ขึ้นต้นด้วยข้อความ และใส่ชื่อเต็ม `"<ชื่อ> <นามสกุล>"` ก็เจอ (ตรวจกับ `AUTO NewHN0926153645` = HN 6931488)
    → ค้นชื่อเต็มแล้ว `totalCount` 0 = ไม่มีผู้ป่วยชื่อนี้ในระบบ (ใช้ใน TC-003 ขั้น 3) · ช่องค้นหาค้นด้วยเลขบัตรประชาชนไม่ได้
  - ไม่เจอ → dropdown เป็น `listbox` ข้อความ "ไม่พบผู้ป่วย" (ขึ้นแบบนี้ตั้งแต่ยังไม่พิมพ์ด้วย — ต้องเช็คจาก API คู่กัน)
  - หน้าจอแสดงแค่หน้าแรก 10 คน (เช่น "คนไข้" มีทั้งหมด 40 คน)
- ระหว่างค้น ช่องจะมี `.ant-select-content-value` ที่ซ่อนอยู่ title เดียวกับผลค้นหา → ต้องระบุ `.ant-select-item-option` ไม่งั้นเจอตัวที่ซ่อน
- **เลือกผู้ป่วยที่มี Visit ER ค้างอยู่ (เปิดวันเดียวกัน)** → ไม่เปิด modal แต่พาไปหน้า Encounter เดิม (`/cortex/next/patients/<HN>?en=<EN เดิม>`) — ไม่สร้าง Visit ซ้ำ
  (ตรวจ 26 ก.ย. 2026 กับ AUTO DupVisit HN 6931503 · Visit ER ค้างข้ามวันยังไม่ได้ลอง เพราะมีแต่ของผู้ป่วยทีม)

## 2.2) ผู้ป่วยทดสอบของทีม (R15) — ตรวจ 26 ก.ย. 2026

- = ผู้ป่วยที่**ชื่อ**ขึ้นต้น "คนไข้" (ผู้ใช้อนุญาตให้ใช้ตอนเทสมือ) · ผลค้น "คนไข้" มี `Jame คนไข้ER01` ปน (นามสกุลขึ้นต้น) → กรองด้วย `firstName`
- หลายคนเป็น `identityVerificationMode: anonymous` (ไม่ระบุตัวตน) · `deceased` เป็น boolean
- **"ไม่อยู่บนบอร์ด ER" ไม่พอ**: บอร์ดแสดงแค่ Encounter ของวันนั้น แต่มีผู้ป่วยทีมที่ Encounter ER ค้าง `in-progress` ตั้งแต่ 16 ก.ย. และที่ Admit อยู่
  (26 ก.ย.: `6931243 คนไข้ C` E69091630927 · `6931252 คนไข้ Y3` E69091630928 · `6931253 คนไข้ Y4` E69091630929 + Admission AN 6902971)
- เช็คงานค้างด้วย API ข้อมูลที่แอปใช้ (GET อย่างเดียว ต้องใส่ `Authorization` เดียวกับที่แอปส่ง — ดึงจาก request ค้นหาผู้ป่วย):
  `GET /generated-emr-api/encounters?filter[hn][equals]=<HN>&perPage=1000` · `GET /generated-emr-api/admissions?filter[hn][equals]=<HN>&perPage=1000`
  → `{ data: [{ en | an, hn, latestStatusCode, ... }] }` · ค่าที่เห็น: `in-progress` / `completed` / `cancelled` (ฟิลด์ `active` คือแถวยังไม่ถูกลบ ไม่ใช่สถานะ)
- `pickTeamPatient()` สุ่มลำดับผู้ป่วยหน้าแรก แล้วเอาคนแรกที่ไม่มี Encounter/Admission ที่สถานะไม่ใช่ `completed` / `cancelled` / `entered-in-error`

## 3) ประเมิน Triage — หน้าผู้ป่วย

ฟอร์ม "คัดกรอง ER" อยู่ใน shadow DOM แต่ `getByRole` ทะลุได้ และ snapshot ของ MCP ก็เห็นช่องในฟอร์ม

**เช็คว่าอยู่หน้า Triage ของ Visit ไหน** (ใช้ใน `expectTriageFormOpen()`): URL `pathname = /cortex/next/patients/<HN>` + `en=<EN>` ·
ใน `main` มี `HN <HN>` (แถบผู้ป่วย) · `<EN>` + `VN <VN>` + `Walk-in` + `<คลินิก> · <วันเวลา>` + คิว (แถบ encounter) ·
`getByRole('tab', { name: 'Triage', exact: true, selected: true })` · `getByRole('heading', { name: 'คัดกรอง ER' })` ·
**หัวข้อ "คัดกรอง ER" ขึ้นก่อนตัวฟอร์ม** (ระหว่างโหลดขึ้น `Loading sbh-general-er-triage-v1...`) → รอ `getByRole('spinbutton', { name: 'Systolic' })` ด้วยถึงจะแน่ใจว่าฟอร์มโหลดเสร็จ

|------|----------------|
| อุปกรณ์ช่วยเหลือ* / ผู้ที่มาด้วย* (ฝั่งซ้าย) | คลิก select แล้ว `getByTitle('ไม่มี', { exact: true })` / `getByTitle('ญาติ')` / `getByTitle('ไม่มีผู้มาด้วย')` — ใส่ `exact` กับ "ไม่มี" กันชนกับ "ไม่มีผู้มาด้วย" |

### 3.0) รายละเอียดฟอร์ม (สำรวจตอนเขียน spec SBH-1021 — 26 ก.ย. 2026) · helper อยู่ที่ `helpers/er-triage.ts`

- ขอบเขตฟอร์ม: `getByRole('tabpanel', { name: 'Triage' })` (แท็บอื่น: Trauma / Non-Trauma / เด็ก / สัตว์มีพิษ — นอก scope SBH-1021) ·
  ช่องฝั่งซ้าย (วิธีการมาถึง / อุปกรณ์ช่วยเหลือ* / ผู้ที่มาด้วย*) อยู่ใน `getByRole('region', { name: 'วิธีการมาถึง' })` นอก tabpanel — combobox ไม่มีชื่อ ลำดับ 0 = อุปกรณ์, 1 = ผู้ที่มาด้วย
  - ตัวเลือก อุปกรณ์: ไม่มี · รถเข็นผู้ป่วย · เปลนอน · อุปกรณ์ช่วยเดิน · ผู้ที่มาด้วย: ไม่มีผู้มาด้วย · ญาติ · ผู้ดูแล · เจ้าหน้าที่ EMS
  - เลือกแล้วบันทึกเข้า Encounter ทันที: `PATCH /cortex-api/er/encounters/<EN>/registration-details` 200 (`assistiveDeviceOptionId` / `accompanyingPersonOptionId`)
- **Vital Signs** (ไม่บังคับ — ผู้ใช้ยืนยัน 26 ก.ย. 2026): spinbutton `Systolic` `Diastolic` `PR` `RR` `Temp` (+ select หน่วย °C/°F) `SpO2` ·
  **Pain score (0-10)** เป็น `<select>` ไม่มีชื่อ ตัวเลือกแรก "Pain score" → `getByRole('combobox').filter({ has: getByRole('option', { name: 'Pain score' }) }).selectOption('3')` ·
  เวลาวัดเติมเองตอนกรอกช่องแรก · ปุ่ม "ใช้ข้อมูลล่าสุด (ภายใน 24 ชั่วโมง)" · Body metric (Weight/Height → BMI/BSA คำนวณเอง)
- **MEWS**: ตาราง 5 แถว `Respiratory rate` / `Heart rate` / `Systolic BP` / `Temperature` / `AVPU` × [ช่วงค่า, คะแนน] (ยังไม่กรอก = `—`) ·
  ค่าทดสอบข้างบน → RR `15-20` 1 · HR `51-100` 0 · SBP `101-199` 0 · Temp `35.0-38.4` 0 · ข้อความ `Incomplete — ยังไม่ได้บันทึก <ช่องที่ขาด>` จนกว่าจะครบ →
  กล่อง `Total MEWS 1 / 14 Low Risk`
- **AVPU**: ปุ่ม `เลือกระดับความรู้สึกตัว` → `A (0)` `V (1)` `P (2)` `U (3)` · **เลือก GCS แล้วระบบตั้ง AVPU ให้เอง** (หัวข้อเป็น "Level of Consciousness (AVPU) — จาก GCS"; GCS 15 → A) ทั้งที่ AC บอกให้ระบุเอง
- **GCS**: หัวข้อ `Glasgow Coma Scale (GCS) *` · E / V / M มี * ทุกช่อง · ปุ่มช่องว่างชื่อ `เลือกคะแนน` · ตัวเลือก (ชื่อปุ่มเต็ม):
  E `4 — ลืมตาได้เอง (Spontaneous)` `3 — ลืมตาเมื่อเรียก/สั่ง (To verbal command)` `2 — ลืมตาเมื่อกระตุ้นด้วยความเจ็บปวด (To pain)` `1 — ไม่ลืมตาเลย (None)` ·
  V `5 — พูดคุยรู้เรื่อง ตอบคำถามถูกต้อง (Oriented)` `4 — พูดคุยสับสน ไม่ปะติดปะต่อ (Confused conversation)` `3 — พูดเป็นคำๆ ไม่เป็นประโยค (Inappropriate words)` `2 — ส่งเสียงไม่เป็นคำพูด (Incomprehensible sounds)` `1 — ไม่ส่งเสียงเลย (None)` ·
  M `6 — ทำตามคำสั่งได้ (Obeys commands)` `5 — ใช้มือปัด/ชี้ตำแหน่งที่เจ็บเมื่อกระตุ้น (Localizes pain)` `4 — ชักแขน/ขาหนีความเจ็บแบบปกติ (Normal flexion / withdrawal)` `3 — งอแขนผิดปกติ ลักษณะ Decorticate (Abnormal flexion)` `2 — เหยียดแขน-ขาผิดปกติ ลักษณะ Decerebrate (Extension)` `1 — ไม่ตอบสนองเลย (None)` ·
  กล่อง `Total GCS E4V5M6 15 / 15 Mild — บาดเจ็บ/ผิดปกติระดับเล็กน้อย` (เปลี่ยน E เป็น 3 → `E3V5M6 14`)
- **Suspect Fast Track** (ไม่บังคับ): ปุ่ม `Not Suspect Fast Track` → กดแล้วเป็นปุ่ม `Suspect Fast Track` [pressed] + ช่อง `Fast Track Type` (combobox "Select fast-track type...") · กดซ้ำกลับเป็นว่าง
- **Trauma Classification ***: radio `Trauma` / `Non-Trauma` — **ค่าเริ่มต้น Non-Trauma** (เหตุผลที่ TC-009 SBH-1754 ถูก Cancel)
- ระดับความเร่งด่วน: ปุ่ม `1 กู้ชีพ` … `4 กึ่งเร่งด่วน` `5 ไม่เร่งด่วน` (ชื่อมีเลขนำหน้า) · โซนแนะนำ `โซนเหลือง ER แนะนำ ใช้ n` [pressed] · หัวจอเปลี่ยน ESI ตามทันที (ก่อนบันทึก)
