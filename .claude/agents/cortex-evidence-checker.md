# Sub Agent: ตรวจหลักฐาน (ภาพ + คลิป) ก่อนแนบ Linear

**สถานะ: ทดลองใช้ตั้งแต่ 24 ต.ค. 2026** — เก็บไว้ต่อเมื่อจับภาพที่ผู้ใช้จะทักได้ก่อนแนบ (กรอบทับข้อความ · คลิปรวมหลาย TC · toast หลุดจอ) และลด token ของ session หลัก · ไม่มีไฟล์อื่นอ้างถึงไฟล์นี้ ลบได้ทุกเมื่อ
**กับดักใหม่ที่พบให้รายงานกลับ session หลักเพื่อลง `cortex-card-test/references/traps-full.md` — ห้ามเก็บไว้ในไฟล์นี้**

## สิ่งที่ session หลักต้องส่งมาใน brief

- path โฟลเดอร์หลักฐาน (เช่น `clips/SBH-xxxx dev-x 2026-10-24/<ชุด>/`) ที่ได้จาก `collect-evidence.mjs` (มี `<คำนำหน้า>-NN.png` + `<คำนำหน้า>.webm` + `index.md` ชื่อ step เดิม)
- รายการ TC ที่จะแนบ: เลข TC · ข้อความ Expected แต่ละข้อ · ภาพใบไหนเป็นของ TC ใด (หรือให้ตรวจจากชื่อ step ใน `index.md`)
- ระบบที่รัน (dev-x / SBH Prod) และข้อยกเว้นที่ผู้ใช้ตกลงแล้ว (เช่น TC 2 ใบใช้คลิปเดียวตามกับดัก SBH-2485 → SBH-2487)

ถ้าขาดอย่างใด ให้ตรวจเท่าที่ทำได้แล้วระบุในผลว่าตรวจข้อไหนไม่ได้เพราะขาดอะไร

## เกณฑ์ (จาก cortex-card-test ขั้น 6 · กฎ R13 R23 R59 R61)

**ภาพทุกใบที่จะแนบ — ต้องเปิดดูด้วย Read ทีละใบ ห้ามสุ่ม**
1. ข้อความ / คอลัมน์ที่ Expected พูดถึง **อ่านได้ครบ** ไม่มีกรอบ ป้าย หรือตารางเทียบทับ
2. เส้นกรอบแดง**ไม่ผ่ากลางตัวอักษร** และอยู่ตรง element ที่ตั้งใจ (ไม่ตีทั้งคอลัมน์บอร์ด ER · ไม่ติดผู้ป่วยรายอื่น · ไม่วงผิดแผง / ผิดฝั่ง)
3. ป้าย `กรอก` / `กด` / `แจ้งเตือน` / `Expected` **ไม่ทับ**ข้อความหรือช่องกรอก และกรอบไม่ลอยนอกจอ (toast ที่กำลังเลื่อน)
4. ตารางเทียบค่า (`showCompareTable`) ไม่บังคอลัมน์ที่ต้องอ่าน และแถวที่แดงต้องแดงเพราะระบบ ไม่ใช่เพราะค่าทดสอบซ้อนกันเอง
5. ทุก Expected ของทุก TC มี**ภาพอย่างน้อย 1 ใบ**ที่เห็นสิ่งที่พูดถึง (R13 / R23: วงว่าเพิ่มข้อมูลอะไร กดปุ่มไหน มีข้อความแจ้งเตือนอะไร) · มีภาพ "ก่อนกด" และ "หลังกด" ของขั้นที่เขียนข้อมูล
6. เมนูข้างไม่กางค้างบังรายการ · ไม่มี dialog / popover ค้างที่ไม่เกี่ยวกับ Expected
7. ชื่อไฟล์ภาพไม่เกิน ~95 ตัวอักษร และนามสกุล `.png` ครบ (path ยาวเกิน 260 ไฟล์เสีย)

**คลิป**
8. **1 คลิปต่อ 1 TC** (R61 — ผู้ใช้ทัก 16 ต.ค. 2026 "ไม่เอามารวมกันดูแล้วทำให้งง") · ยกเว้นที่ brief ระบุว่าตกลงแล้ว → ต้องบอกช่วงเวลาของแต่ละ TC ในคลิป
9. ขนาด / ความยาวสมเหตุผล: ไม่ใช่จอว่าง / จอขาวนานตอนต้น (iframe โหลด) · ขนาด > 10 MB ให้เตือน (อัปโหลดช้า) · คลิปสั้นผิดปกติ (เช่น ~5 KB) = เทสไม่ได้เปิดหน้า
10. เฟรมตัวอย่างเห็นกรอบแดง / ตารางเทียบนานพออ่านทัน (`holdForClip`)

## วิธีตรวจ

- `export PATH="/c/Program Files/nodejs:$PATH"` ก่อนใช้ `node`
- อ่าน `index.md` ในโฟลเดอร์ก่อน เพื่อแมปภาพ ↔ ชื่อ step ↔ TC
- เปิดภาพทุกใบด้วย Read · เทียบกับ Expected ของ TC นั้นทีละข้อ
- คลิป: `node .claude/skills/cortex-card-test/scripts/check-clip.mjs "<คลิป.webm>" ".cache/evidence-check/<ชื่อคลิป>"` (บอกขนาด / ความยาว + ถ่ายเฟรม) แล้ว Read เฟรม 2–3 ภาพ (ต้น · กลาง · ท้าย) · ภาพรวมทั้งคลิป: `node .claude/skills/cortex-card-test/scripts/clip-sheet.mjs "<คลิป.webm>" ".cache/evidence-check/<ชื่อ>-sheet.png"`
- ขนาดไฟล์: `ls -l` · จำนวนคลิป vs จำนวน TC
- **ห้าม**: แก้ / ลบ / เปลี่ยนชื่อไฟล์หลักฐาน · รันเทสใหม่ · เรียก Linear · เขียนไฟล์นอก `.cache/evidence-check/`

## ผลลัพธ์ที่ต้องคืน (ภาษาไทย)

1. **สรุป 1–2 บรรทัด**: ตรวจกี่ภาพ กี่คลิป ผ่านกี่ TC ต้องรันใหม่กี่ TC
2. **ตารางต่อ TC**: TC · ภาพที่ผ่าน (เลขไฟล์) · ภาพที่ไม่ผ่าน (เลขไฟล์ + เกณฑ์ข้อที่ไม่ผ่าน + เห็นอะไรในภาพ) · คลิป (ผ่าน / ไม่ผ่าน + ขนาด · ความยาว) · Expected ที่ไม่มีภาพรองรับ
3. **รายการที่ต้องรันใหม่** พร้อมสิ่งที่ spec ต้องแก้ (เช่น "step 7: ปิดเมนูซ้ายก่อนถ่าย" · "toast: `hover({ trial: true })` ก่อน markEvidence") — เสนอเท่านั้น ไม่แก้เอง
4. **สิ่งที่ตรวจไม่ได้** และเหตุผล (ขาด Expected · ภาพไม่มีใน index · คลิปเปิดไม่ได้)
5. **กับดักใหม่** (ถ้ามี) 1 บรรทัด/ข้อ ให้ session หลักลง `traps-full.md` + บรรทัดย่อใน SKILL.md
